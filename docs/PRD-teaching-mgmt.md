# PRD：智能排课表 + 考勤课时统计 + 教案课件资源库

## 项目信息

| 项 | 值 |
|---|---|
| **项目名称** | teacher_workstation_modules |
| **技术栈** | Vue 3 (Composition API) + Vite 5 + TailwindCSS 3 (darkMode: 'class') + Vue Router 4 + Pinia 2 + localforage (IndexedDB) + Chart.js + PWA |
| **目标平台** | 移动端 PWA（max-w-md，底部 Tab 导航） |
| **机构规模** | 中型教培机构（10-50 人） |
| **原始需求** | 在现有教师个人工作台 PWA 应用基础上，新增三个模块：智能排课表（拖拽式周课表 + 冲突检测）、考勤课时统计（签到打卡 + 课时累计 + 消耗预警）、教案课件资源库（轻量索引层 + 金山文档外链跳转） |

---

## 一、产品目标

为中型教培机构教师提供**排课→考勤→课时消耗→教学资源**的一体化管理工具，在现有课程记录工作台上闭环教学流程：拖拽排课解决多教室多教师冲突排班痛点，考勤签到自动累计课时消耗并预警续费，资源索引层让教案课件一键可达，三个模块数据互通形成完整教学链路。

---

## 二、用户故事

### 模块一：智能排课表

- **US-1.1**：作为一名排课老师，我想在周课表网格上拖拽课程卡片到不同时段，这样我能直观地安排一周课程而不需要手动填写星期和时间段。
- **US-1.2**：作为一名排课老师，我想在排课时自动检测教师时间冲突和教室时间冲突，这样我不会把同一个老师或同一间教室排在同一时段。
- **US-1.3**：作为一名排课老师，我想按教室筛选查看课表，这样我能快速确认某间教室的排班情况。

### 模块二：考勤课时统计

- **US-2.1**：作为一名授课老师，我想在上课时快速对学生进行签到/请假/缺勤标记，这样我能记录每节课的出勤情况。
- **US-2.2**：作为一名老师，我想看到每个学生的剩余课时和消耗进度，这样我能在课时不足时及时提醒续费。
- **US-2.3**：作为一名老师，我想查看月度考勤统计看板，这样我能了解整体出勤率和课时消耗趋势。

### 模块三：教案课件资源库

- **US-3.1**：作为一名老师，我想把教案和课件的金山文档链接按学科/年级/类型分类录入，这样我下次备课能快速找到对应资源。
- **US-3.2**：作为一名老师，我想通过关键词搜索资源库，这样我不用翻找分类就能定位到需要的教案。
- **US-3.3**：作为一名老师，我想在排课记录上关联教案链接，这样上课时能一键跳转到对应教案文档。

## 三、需求池

### P0 — 必须有（上线最小可用）

#### 模块一：智能排课表

| 编号 | 需求 | 说明 |
|---|---|---|
| S-P0-1 | 周课表网格视图 | 周一至周日 × 时段（可配置时段列表）的网格布局，每个格子可放置课程卡片，卡片显示课程名/教师/教室 |
| S-P0-2 | 拖拽排课 | 长按课程卡片可拖拽到目标格子，松手即保存；支持在空白格新建课程 |
| S-P0-3 | 排课编辑表单 | 新建/编辑排课项：课程（复用现有 `course_list_v1`）、教师、教室、星期、时间段（复用现有 TimeWheelPicker）、课型（常规/零售）、关联模板（复用现有 `lesson_templates_v1`） |
| S-P0-4 | 教师冲突检测 | 拖拽/保存时检测同一教师同一时段是否已排课，冲突时阻止保存并红色高亮提示 |
| S-P0-5 | 教室冲突检测 | 拖拽/保存时检测同一教室同一时段是否已排课，冲突时阻止保存并红色高亮提示 |
| S-P0-6 | 数据持久化 | 排课数据存储到 localforage，key 为 `schedule_v1`；排课项结构在现有 timetable 基础上扩展 `teacher`、`classroom`、`studentGroup` 字段 |
| S-P0-7 | 排课→考勤联动 | 排课项可生成当日考勤任务（根据排课的星期 + 当前日期匹配），考勤模块直接读取排课数据 |

#### 模块二：考勤课时统计

| 编号 | 需求 | 说明 |
|---|---|---|
| A-P0-1 | 当日考勤任务列表 | 根据排课数据自动生成今日考勤任务列表（课程名/时间/教室/教师/学生名单），支持手动添加临时考勤任务 |
| A-P0-2 | 学生签到/请假/缺勤 | 点击考勤任务进入学生列表，逐个标记出勤状态；支持"全部签到"快捷操作 |
| A-P0-3 | 课时账户管理 | 每个学生在每门课程下有课时账户（总课时/已消耗/剩余），签到时自动扣减课时，请假不扣减 |
| A-P0-4 | 课时消耗预警 | 学生剩余课时低于阈值（默认 4 课时）时，在考勤列表和首页以橙色/红色标记提醒 |
| A-P0-5 | 考勤数据持久化 | 考勤记录 key 为 `attendance_v1`；课时账户 key 为 `student_hour_accounts_v1` |
| A-P0-6 | 考勤看板（简版） | 显示今日/本周出勤率、课时消耗总量、预警学生数 |

#### 模块三：教案课件资源库

| 编号 | 需求 | 说明 |
|---|---|---|
| R-P0-1 | 资源列表页 | 卡片式列表展示所有资源条目，显示标题/学科/年级/类型标签 |

| R-P0-4 | 分类筛选 | 按学科/年级/类型组合筛选，下拉选择器 |
| R-P0-5 | 关键词检索 | 顶部搜索框，模糊匹配标题和备注 |
| R-P0-6 | 数据持久化 | 资源数据 key 为 `resource_index_v1` |

#### 跨模块 / 导航

## 四、UI 设计要点

### 整体导航结构

```
┌─────────────────────────────┐
│      教学 Tab 顶部导航       │
│  ┌──────┬──────┬──────┬──────┐
│  │课程记录│ 排课 │ 考勤 │资源库│  ← Segmented Control
│  └──────┴──────┴──────┴──────┘
├─────────────────────────────┤
│                             │
│      子模块内容区域          │
│    （router-view 渲染）      │
│                             │
├─────────────────────────────┤
│  工作台  教学  待办  我的    │  ← 底部 TabBar（不变）
└─────────────────────────────┘
```

- 顶部 Segmented Control 使用 `overflow-x-auto`，宽度不够时可横向滚动
- 选中态：`bg-indigo-600 text-white`，未选中：`bg-slate-100 text-slate-600`
- 暗色模式：选中 `bg-indigo-500 text-white`，未选中 `bg-slate-800 text-slate-400`

- 网格采用 CSS Grid，7 列（星期）× N 行（时段）
- 课程卡片：圆角小卡片，显示课程名（粗体）+ 教师 + 教室，背景色按课程区分（复用 `course_list_v1` 顺序分配颜色）
- 空白格：虚线边框，点击可新建排课
- 拖拽交互：长按 300ms 触发拖拽，卡片半透明跟随手指，目标格高亮边框；松手时检测冲突
- 冲突提示：冲突格子红色闪烁边框 + Toast "教师[张三]在该时段已有[Python]课程"
- 横向滚动：7 列在小屏可能过窄，默认显示 5 列（周一至周五），左右滑动查看周末

### 详细数据关系

| 数据关系 | 说明 |
|---|---|
| **排课 → 考勤** | 排课项 `{weekday, slot, course, teacher, classroom, studentGroup}` 按星期匹配当日日期，生成考勤任务。考勤记录 `attendance_v1` 中每条记录引用排课项 ID（`scheduleItemId`）。 |
| **排课 → 录课（现有）** | 排课卡片长按菜单"录课"，复用现有 `onAddFromTimetable` 逻辑，自动填充课程/时间/模板信息到课程记录编辑器。 |
| **排课 → 资源库（P1）** | 排课项可选字段 `resourceId` 关联资源库条目，排课卡片显示关联教案标记，点击可跳转。 |
| **考勤 → 课时账户** | 签到时根据课程 `classHours`（从排课项或模板获取）扣减学生课时账户的 `remainingHours`。请假/缺勤不扣减。 |
| **考勤 → 预警** | 课时账户 `remainingHours ≤ threshold` 时触发预警，在考勤列表和首页提示。 |
| **资源库 → 课程记录** | 资源库独立运作，但资源条目的学科字段复用 `course_list_v1`，保持分类一致性。 |
| **学生数据复用** | 考勤模块的学生名单来自排课项的 `studentGroup`（从 `common_student_names_v1` 选择），课时账户按 `学生名 + 课程名` 唯一索引。 |

## 六、导航方案

### 方案：教学 Tab 内子路由 + 顶部 Segmented Control

**路由结构变更：**

```
现有路由:
/                → 工作台 (DashboardView)
/teaching        → 教学 (TeachingView)        ← 整合为子路由
/todos           → 待办 (TodoView)
/settings        → 我的 (SettingsView)

变更后路由:
/                → 工作台 (DashboardView)
/teaching        → 重定向到 /teaching/records
/teaching/records    → 课程记录 (现有 TeachingView 内容重构)
/teaching/schedule   → 智能排课表 (ScheduleView)
/teaching/attendance → 考勤课时统计 (AttendanceView)
/teaching/resources  → 教案课件资源库 (ResourceView)
/todos           → 待办 (TodoView)
/settings        → 我的 (SettingsView)
```

**实现要点：**

1. **路由配置**：在 `router/index.js` 中为 `/teaching` 添加 `children` 子路由，所有子路由 `meta.tab: 'teaching'` 确保底部 Tab 高亮"教学"。
2. **TeachingLayout 组件**：新建 `TeachingLayout.vue` 作为子路由的布局容器，包含顶部 Segmented Control + `<router-view>`。原有 TeachingView 的逻辑拆分到 `CourseRecordsView.vue`。
3. **Segmented Control**：四个选项横向排列，选中态使用 `router-link-active` 样式判定，点击切换路由。
4. **页面过渡**：复用现有 `page-slide` Transition 动画。
5. **状态保持**：使用 `<router-view>` 默认不缓存；如需缓存各子模块滚动位置，可后续引入 `<keep-alive>`（P2）。

**不新增第 5 个 Tab 的理由：**
- 手机端底部 Tab 超过 4 个会挤压可点击区域，影响触控体验
- 三个新模块都属于"教学"范畴，逻辑归属一致
- Segmented Control 是移动端常见的二级导航模式，用户认知成本低

### 与现有功能的融合点

| 现有功能 | 融合方式 |
|---|---|
| 今日课表提示（首页日历页） | 数据源从 `my_timetable` 切换为 `schedule_v1`（兼容旧数据迁移） |
| 课表弹窗（TimetableModal） | 保留作为快速查看入口，数据源同步切换；新建/编辑跳转到排课模块 |
| 从课表一键录课（onAddFromTimetable） | 排课卡片长按菜单触发，逻辑不变 |
| 学生管理（common_student_names） | 考勤模块学生选择复用此数据源 |
| 课程分类（course_list_v1） | 排课和资源库均复用此分类 |
| 课程模板（lesson_templates_v1） | 排课编辑表单复用模板选择 |
